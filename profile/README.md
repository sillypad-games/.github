# TJ Dev Studio

**We declare worlds. The engine renders them.**

Every wall, platform, tree, and waterfall in our games is data first, geometry second. We don't place objects in an editor — we describe them in JSON. When we want to change the world, we change the schema. The engine is the runtime.

---

## What We Ship

A **100-player frog battle royale** built in Godot 4. A 200-meter living civilization with 12 NPCs, patrol routes, lore, and a 25-meter ancient tree at its center. Every object generated at runtime from structured data. Zero hardcoding. Zero hand-placement.

We wrote a **parallel AI agent pipeline** to build it faster. We built the **infrastructure** when the infrastructure didn't exist. We open-sourced everything that might help someone else ship harder.

---

## Open Source

**[blocks](https://github.com/TJ-Dev-Studio/blocks)** — Composable Block primitive library for Godot 4. 551 tests. The foundation of everything we render. Declarative world construction at any scale. Use it to build your world.

**[claude-swarm](https://github.com/TJ-Dev-Studio/claude-swarm)** — Orchestrate parallel AI agents across a shared codebase. Task definitions, claim locks, file ownership, worktree management. Ship together without stepping on each other.

**[godot-agent-kit](https://github.com/TJ-Dev-Studio/godot-agent-kit)** — AI agent toolkit for Godot 4 visual iteration. Agents that see what's on screen and interact with your scenes programmatically.

**[godot-preview](https://github.com/TJ-Dev-Studio/godot-preview)** · **[godot-interact](https://github.com/TJ-Dev-Studio/godot-interact)** — Headless Godot 4 screenshot capture and input simulation.

**[tapestry](https://github.com/TJ-Dev-Studio/tapestry)** — Persistent concept graph for LLM pipelines. Rich, connected memory for agents. Zero dependencies.
