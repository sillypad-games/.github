# SillyPad Games

**We build worlds from data. The engine renders them.**

Every wall, platform, tree, and waterfall in our games is defined in a declarative world system — a 7-level spatial hierarchy from elements to assemblies to structures to zones. Hand-placed or procedurally generated, everything flows through the same pipeline: structured JSON in, living 3D world out.

---

## What We Ship

A **100-player frog battle royale** built in Godot 4. A 200-meter living civilization with 12 NPCs, patrol routes, lore, and a 25-meter ancient tree at its center. 5000+ blocks defined as data, rendered at runtime through a composable pipeline. One system for hand-crafted villages and procedural forests alike.

We built the **tooling** to make AI agents first-class collaborators in game development — visual capture, input simulation, and structured iteration loops that let agents see and interact with 3D scenes.

---

## Open Source

**[blocks](https://github.com/sillypad-games/blocks)** — Composable block primitive library for Godot 4. 551 tests. Declarative world construction at any scale — geometry, connections, messaging, visual state. The foundation of everything we render.

**[godot-agent-kit](https://github.com/sillypad-games/godot-agent-kit)** — AI agent toolkit for Godot 4 visual iteration. Capture screenshots, simulate input, and iterate on game visuals — all without a display.

**[godot-preview](https://github.com/sillypad-games/godot-preview)** · **[godot-interact](https://github.com/sillypad-games/godot-interact)** — Headless Godot 4 screenshot capture and input simulation.

**[tapestry](https://github.com/sillypad-games/tapestry)** — Persistent concept graph for LLM pipelines. Rich, connected memory for agents. Zero dependencies.
